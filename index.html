02 / Indice n°1 — Les bases

Qu'est-ce qu'une API ?

API (Application Programming Interface) : un intermédiaire qui permet à deux programmes de communiquer.

L'analogie du restaurant

  • Le client = vous, l'application de l'étudiant
  • Le serveur du restaurant prend la commande et rapporte le plat = l'API
  • La cuisine prépare le plat = le serveur informatique
  • La réserve où sont les ingrédients = la base de données

Vous n'entrez jamais en cuisine : vous passez par le serveur. Avec une API, c'est pareil.

Le trajet d'une requête

Le vocabulaire du détective

REST API

Une façon standard d'organiser une API : des URLs claires + des méthodes HTTP.

GET/api/books

Ressource

La « chose » qu'on manipule. Ici : les livres.

/api/books
/api/books/42

Requête HTTP

Le message du client : une méthode + une URL (+ parfois des données).

GET/api/books/42

Réponse HTTP

Le message du serveur : un code de statut + des données.

200 OK

JSON

Un format texte simple pour échanger des données : des paires clé : valeur.

{ "title": "Clean Code" }

05 / Laboratoire

Le labo des réponses HTTP

Chaque réponse contient un code de statut : un nombre qui dit au client ce qui s'est passé.

2xx Succès 4xx Erreur du client — la demande pose problème 5xx Erreur du serveur

401 ou 403 ? Ne pas confondre

401
« Qui êtes-vous ? »

Pas authentifié : vous n'avez pas prouvé qui vous êtes (pas connecté, identifiants absents ou invalides).
Vous entrez sans carte de bibliothèque.

403
« Pas le droit. »

Authentifié, mais pas autorisé : le serveur sait qui vous êtes, l'action vous est interdite.
Votre carte étudiant n'ouvre pas la réserve du personnel.
